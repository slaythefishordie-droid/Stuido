# 初版开发计划与 YouTube 原型补充（用户原文）

你是 Knowledge Studio 项目的开发负责人。请依据以下需求检查现有工程并逐阶段实现。用户主要用中文交流，请用中文解释进度、实现结果和问题，代码标识符及协议字段使用英文。

一、工作方式

1. 先读取仓库中的 AGENTS.md、README 和现有代码，检查已有实现，不要擅自重建项目或覆盖已有工作。
2. 先列出已有功能、缺失功能和会影响实施的冲突，然后立即推进可执行的工作。
3. 常规、可逆的实现细节由你判断；只有无法从工程和需求中判断、且会显著影响产品方向的问题才询问我。
4. 每个阶段完成一个可运行、可验证的闭环。不要一次生成大量只有外观、没有实际数据行为的页面。
5. 不要擅自新增一级卡片类型、AI 聊天功能或云同步功能。
6. 如环境不能编译、运行或真机验证，明确说明；不得把静态检查描述成运行成功。
7. 每阶段报告：完成内容、验证结果、剩余问题、下一步。保持简洁。

二、产品定位

Knowledge Studio 是 iPad 优先、本地优先的个人知识整理与连接中心。

核心流程：
- 自己学习：PDF / EPUB / 视频 → 快速 Mark → My Inbox → 集中整理。
- AI 预处理：在独立的 ChatGPT 中整理 → 手动导入 JSON → AI Inbox → 核对筛选。
- 整理后：收藏为卡片 → 关联资料、项目和其他卡片 → 用户主动选择是否加入复习。

不可改变的原则：
- 标记不等于建卡，建卡不等于加入复习。
- ChatGPT 在 App 外独立使用，不接入聊天或模型 API。
- App 使用 PDF / EPUB / 视频专用学习界面，不开发完整浏览器。
- 不接入字典 API；使用词典外链与手动保存。
- 所有主要界面都可以快速建卡。
- 数据必须易查找、易整理、易清理，并可备份恢复。

三、四类卡片

一级内容类型只能有以下四类：

1. word：单词
   - 内容字段：word、definition_en、example_en。
   - 学习主体只展示英文例句和英文释义。
   - 单词作为记录标识保存；出处可在详情查看。
   - 不自动添加中文释义等额外学习栏目。

2. expression：语料
   - 内容字段：text。
   - 展示原句和出处。
   - 关注“怎样表达”。

3. keyword：关键词
   - 内容字段：term、可选 explanation。
   - 保留出处。
   - 用于理解概念及项目关键词思维导图。

4. key_sentence：关键句
   - 内容字段：text、可选 explanation。
   - 保留原始出处。
   - 关注思想、观点或论断。

共用字段：
ID、语言、标签、出处引用、个人笔记、发现来源、创建及修改时间。

默认一张卡只有一个主类型，允许关联其他卡片。
summary、argument、question、reflection 等不得新增为一级类型。
总结、论证、问题和反思可放入有关卡片的说明或笔记。

四、独立的数据维度

不要把以下维度混成一个枚举：

- 内容类型：word / expression / keyword / key_sentence。
- 发现来源：AI / 自己 / 两者。去重合并后保留双方来源。
- 整理状态：待整理 / 已收藏 / 已归档。
- 复习状态：未加入 / 复习中 / 已暂停。

“AI 发现”不等于“AI 原创”：
必须区分原文摘录、AI 解释、AI 创作、用户提供内容。
AI 写的例句或改写不得冒充原文；AI 想法不得冒充用户个人笔记。
内容可能由多个来源构成，必要时在字段级记录来源身份。

五、数据架构

核心对象：
Project、Source、Mark、Card、Relation、Review Record。

可按实现需要增加内部记录：
导入批次、待确认导入条目、复习调度状态、图谱节点及布局等。
这些不是新的卡片类型。

关系要求：
- Project 与 Card 独立，卡片不必属于任何项目。
- Source 原始资料只保存一份，通过关联复用。
- Project 支持新增、编辑、删除，以及关联或移除 Source、Card 和 Relation。
- Mark 保留来源定位，不必生成 Card。
- Card 可以引用来源及 Mark，也可以是独立创建的内容。
- 每个 Project 支持自由创建和编辑关键词思维导图。
- 图谱节点位置与知识关系分别保存。
- 移除图谱节点不默认删除原卡片。
- 删除项目、解除关联、删除内容是不同操作。
- 所有正式对象使用稳定 ID。

将界面、业务规则和持久化职责分开，避免页面自行维护重复数据。

六、ChatGPT JSON 导入协议

优先固定协议，再开发依赖它的界面。

外层字段：
schema_version
package_id
title
sources
cards
relations

每张候选卡片包含：
id
type
content
source_refs
language
tags
provenance
note（可选的导入说明，不自动当成用户笔记）

要求：
1. 使用严格 JSON Schema，四种 content 通过 type 区分并校验。
2. 包内 ID 在确认入库时映射到正式 ID，正确重映射关系引用。
3. 出处采用有类型的定位结构：
   - PDF：页码，并明确页码计数规则。
   - EPUB：可获得的章节或阅读器定位信息。
   - 视频：以秒为单位的时间定位。
4. ChatGPT 不知道的位置必须留空，不能生成伪造页码、时间戳或阅读器定位。
5. AI 生成的解释或例句明确标记，原文摘录尽量保留原样。
6. relations 只能引用包内合法对象；如果支持外部对象引用，必须显式区分并验证。
7. AI 导入不能执行删除操作，也不能创建虚构的 Mark 或 Review Record。
8. 项目归属由用户在导入界面选择或确认；不自动加入复习。
9. 文件导入和粘贴 JSON 共用同一个解析器。
10. 未支持的协议版本、未知类型、缺失必填字段、重复 ID、无效引用都要明确报错。
11. 缺失出处信息可进入待补全状态，但不能假装能够回跳。
12. 导入确认应原子化，失败时不能留下半份正式数据。
13. 重复批次与内容重复分别处理。不要仅依赖 package_id 去重，也不要自动覆盖用户修改。
14. 预览时提供跳过、保留、合并等适用操作。

导入流程：
解析与校验 → 匹配 Source → 重复检测 → AI Inbox 预览 → 用户确认 → 正式入库。

同时交付：
- JSON Schema。
- 中文 ChatGPT 整理提示词，要求只输出协议 JSON。
- 覆盖四种类型的合法样例。
- 缺失字段、无效引用、重复导入等错误或边界样例。
- 协议版本和迁移说明。

这几项必须使用同一套定义，不能各写各的。

七、页面职责

- Today：继续学习、待整理、到期复习入口。
- Library：Project 与 Source 管理。
- My Inbox：自己的待整理标记与内容。
- AI Inbox：AI 导入的待确认内容。
- Dictionary：单词与关键词视图。
- Corpus：语料与关键句视图。
- Knowledge Map：知识关系及项目关键词思维导图。
- Review：用户主动选入的复习内容。
- Data Manager：独立、可视化的数据管理。
- Quick Capture：全局快速建卡。

这些页面读取同一套数据，不复制存储。
双 Inbox 表示不同发现来源的整理入口，不建立两套独立知识库。

八、学习与数据管理

学习：
- PDF / EPUB 支持阅读、选文高亮、标记与出处回跳。
- 本地视频与 YouTube 支持专用播放界面、时间戳标记与回看。
- 精确定位由阅读器或播放器生成。
- 先完成 PDF 闭环，再扩展 EPUB 和视频。
- 任何学习界面均应尽量避免要求用户立即填写复杂表单。

Data Manager：
- 管理 Project、Source、Mark、Card、Relation、Review 数据。
- 支持筛选、批量整理、归档、删除和恢复。
- 删除前显示会影响的对象与关联。
- 默认避免隐式级联删除。
- 支持回收站、备份和恢复。
- 备份包含必要的原始文件、对象、关系及版本信息。
- 恢复需要验证数据与关联完整性。
- 引用的资料暂不可用时，保留卡片内容与出处信息，并明确提示。

复习：
- 用户主动加入或退出。
- 退出复习不删除卡片。
- 原方案采用 FSRS；接入前确认合适实现及其接口。
- 四类卡片的具体正反面尚未最终确定，先提出简洁、符合既定展示要求的方案，不冒充已有结论。
- 调度状态与实际复习记录分别保存。

九、技术与环境

此前建议原生 SwiftUI 路线，候选组件包括：
PDFKit、Readium、AVKit / WebKit，以及适合的本地持久化方案。

这些是技术候选，不是所有依赖都已锁定：
- 如果已有工程，优先沿用并评估。
- 如果没有工程，再确定最低 iPadOS 版本、数据库和组件版本。
- 查阅所选依赖的官方文档，验证兼容性和实现能力。
- 用户目前有 Windows 与 iPad，已完成 iTunes Wi-Fi 同步。
- 不要据此假设已有可编译工程或可安装 IPA。
- 首先核实 macOS 构建、签名和设备安装渠道。
- 不虚构已完成的构建、签名、安装或真机测试。
