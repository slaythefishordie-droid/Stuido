# iPad 性能与数据兼容验收

状态：方案，尚无本轮真机测量。Linux 结果不能替代本表。先阅读根目录 PERFORMANCE_AUDIT.md 与 PERFORMANCE_RESULTS.md；既有功能清单沿用 `docs/quality/v3.7.0.md` 的 60 项。

## 环境和安全

1. 先从 v3.7.0 导出备份，将原数据库、assets 与 Safari App Group 文件另外存档；保留 v3.7.0 IPA 与相同 AltStore 签名身份。不要卸载装有真实资料的 App，也不要用性能夹具覆盖真实库。
2. 在独立测试容器/测试设备准备轻、中、大数据集：100 / 2,000 / 10,000 Cards，分别约 200 / 4,000 / 20,000 Marks，10 / 200 / 1,000 Sources；所有四种卡片、双 Inbox、项目/关系/复习历史均包含。大型图另备 500 与 2,000 节点；文档另备 1,000 页文字 PDF、300 页扫描 PDF、大型中英 EPUB、视频、三种封面和 Pencil 墨迹。仓库基准只生成核心数据库，不宣称包含真实图片和文档压力。
3. 固定同一 iPad 型号、iPadOS、显示缩放、亮度、窗口大小、网络、资料集和 Release 配置。记录电量、充电状态、Low Power Mode、系统热状态、可用内存及构建 SHA。顺序交替测试基线和候选，防止热积累偏差。iPad 上不要运行 Linux 基准后冒充 UI 数据。
4. 使用 Xcode Instruments 可分析的本地 Release 签名构建；AltStore 安装验证是独立项目，免费签名不保证可以被 Instruments 附加。用相同源码构建两种安装方式，分别记录权限、共享与性能。测试后还原偏好。

## 采样与判断

每个模式、规模至少 3 次独立运行。冷启动/首次打开单独记录，不能混入热缓存。普通点击至少 100 次、常用导航至少 30 次，保留原始事件后再计算 P50/P95；滚动每次连续 60 秒，长时测试 60 分钟。记录数值与录像，不能以“感觉顺滑”替代数据。

| 任务 | 工具与操作 | 记录 |
|---|---|---|
| 导航、侧边栏、卡片、Data Manager | SwiftUI + Time Profiler；展开/收起、快速往返、搜索、切换类别、跨页多选 | 点击至反馈/可交互内容时间，body 更新原因、主线程阻塞；参考 P95 100 ms、导航 300 ms，不是未测保证 |
| 长列表/封面/地图 | Animation Hitches + Core Animation；两种资料布局、三种封面、白板缩放/拖动 | hitch duration/ratio、实际系统刷新率、CPU；不强制 30/60/120 FPS |
| 阅读器 | Time Profiler + Points of Interest / os_signpost；冷开 PDF/EPUB、滚动缩放、翻章、选区、四种高亮、OCR、墨迹、来源回跳 | `PDFOpen`、`CoverLoad`、`LibraryCommit` 时段，PDFView 主线程布局成本、阅读位置写入时触控是否受阻 |
| 内存 | Allocations、Leaks、VM Tracker；反复打开关闭 30 个不同文档、滚动 1,000 个封面、清缓存、模拟内存警告 | 峰值/稳定占用、关闭后滞留对象、CGImage/PDFDocument/task 数量。缓存预算不等于进程 RSS 上限；可见 View 和系统渲染缓存另计 |
| 能耗 | Energy Log / Energy Impact，同亮度不充电，普通与低电量各 30–60 分钟 | CPU、唤醒、热状态、电量变化、后台活动；Lounge 无提醒时 bookkeeping 预期约 2 次/分钟，但这不是整个 App 的唤醒实测 |
| Safari / 多窗口 | Safari 原页连续 100 个 QuickMark，修改备注/删除/重试，切回 App，多窗口并行编辑 | 完整、去重、顺序/修订正确，`SafariReceive` 时段；共享容器损坏必须可见报错且保留文件 |

signpost 子系统为 `org.knowledge-studio.prototype`，类别为 `Performance`；日志不包含用户资料、标题、路径或 URL。开启 Thread Performance Checker / Main Thread Checker（另一次诊断运行），不要拿额外检查器开销当 Release 性能。

## 普通 / Low Power Mode / 热压力

- 在设置切换系统低电量模式，前后台各切一次；检查非关键封面并发从 2 降至 1，缓存预算下降，已打开阅读器、文字清晰度、标注、视频、基础动画保持功能一致。
- 热状态 serious/critical 的策略可由单元测试验证映射；真实设备必须记录系统实际状态，不能用单元注入当真机热测试。不要人为危险加热设备。
- 内存警告清理的是可重建图片和进行中的非关键封面任务，不能删除用户自选封面、资料或未保存编辑；压力缓解并重新激活后恢复正常预算。
- 比较相同刷新率条件下的卡顿分布，允许系统降低刷新率，不将不同条件下 FPS 绝对值直接比较。

## 必须通过的数据与行为回归

- 导入四类 JSON、重复导入、引用重映射；My Inbox 整理/建卡/归档/撤销，AI Inbox 审核；自选复习连续评分、旧编辑不覆盖新 FSRS 结果。
- 交替滚动 EPUB A→B→A，立刻返回/锁屏/切后台并重开。最后位置一致；生成 Mark 后排队的旧位置不能覆盖更新的定位。多窗口编辑和阅读交错；保存失败显示错误，恢复空间/访问后重试成功。
- 在位置写入期间导出备份，再在隔离容器恢复，核对四类卡片、阅读位置、墨迹、封面、关系、复习历史和资源 SHA；不要执行真实用户资料的破坏性测试。
- 软删除、回收站恢复、永久删除的影响确认不变；备份失败、无效引用、外部损坏仍报告，不能静默创建空库。
- 关闭文档后没有持续页面任务；快速进入退出尚在打开的 PDF，不出现旧文档附着、新页跳转错位或原锚点变化。
- 三种封面相互切换、重生成、修改封面后立刻滚动、内存警告后再打开。清缓存保留用户原图和原文档，原始封面与作者字段可恢复。
- Lounge 提醒在准确截止时间出现；暂停/恢复/取消、前后台/多场景、空纸条列表、磁盘失败重试均无高频忙循环。音乐/视频控制、A–B、全部 QuickMark 功能不受低电量策略影响。
